# go-bunnynet

Unofficial Go client for the Bunny.net core API, generated from the public OpenAPI document. For using the client from an agent, read [.agents/skills/go-bunnynet/SKILL.md](.agents/skills/go-bunnynet/SKILL.md). This file covers changes to the repository.

## Architecture

One generated package, `bunnynet`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://core-api-public-docs.b-cdn.net/docs/v3/public.json` to `api/openapi.json`, validates the document, then oapi-codegen with `config.yaml` writes `client.gen.go`. All operations in the core spec are generated. No spec patch is applied.

## Stack

- Go 1.26.10.
- oapi-codegen v2.8.0, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the root package.
- `client_test.go`, `example_test.go`: HTTP contract tests and the README example.
- `scripts/`: spec download, lint and security scans.
- `api/`: downloaded spec, gitignored.
- `vendor/`: vendored dependencies, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Core requests use `https://api.bunny.net` and the `AccessKey` header. Storage passwords and library keys are for separate APIs.
- Some operations also declare an alternative `Authorization` scheme. Auth is supplied through a request editor.
- Method names follow operation IDs with punctuation removed, for example `PullZonePublicIndexAllWithResponse`.
- Pull-zone listing describes an object for `page > 0` but declares only an array schema. Use the raw method and decode the body for paginated listing. Leave `Page` unset for typed decoding.
- Success responses without schemas expose status and raw body. Adding a pull zone has no typed success field.
- Keep the `number` to `float64` mapping in `config.yaml`.
- `make generate` downloads the current spec. Review the generated diff after each regeneration.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
